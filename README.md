## 每个赚钱的在线业务，都是一份答案

创业最难的不是把东西做出来，是知道该做什么。

每当一个 SaaS 开始有收入，就说明某个需求被真金白银验证过一次。它的落地页写着客户在焦虑什么，定价页写着客户愿意付多少，功能列表写着客户真正在乎什么 —— 这些信息全都公开摆着，只是很少有人把它当成一份答案来读。

Kakashi 读的就是这个：把一个正在跑的业务从外到内拆开，还原成一张可以照着走一遍的地图。

## 拆完拿到什么

丢进去一个网址，拿回一份结构化的拆解：

- **它在卖什么** —— 一句话说清的产品定义，和它真正解决的那个问题
- **卖给谁** —— 目标客户、使用场景、付费动机
- **怎么收钱** —— 定价结构、套餐设计、免费与付费的分界线
- **靠什么留住人** —— 核心功能，以及客户在哪一步被说服
- **怎么搭起来** —— 技术栈与大致实现路径
- **还差什么** —— 它的弱点在哪，哪里可以做得更便宜、更合适另一个市场

## 拆解之后

拆解只是前半程。知道一门生意怎么运转之后，后半程是决定拿哪一部分重做：

同一个需求，换一个人群；同一个产品，换一个市场；同一个模式，换一种交付方式。

目标是把「看到一个生意」到「做出一个能跑的版本」之间的路，从几个月压缩到几天。

## 边界

复刻的对象是公开的商业逻辑和产品结构，不是别人的代码、内容和品牌。看得见的部分用来理解，不该碰的部分不碰。

## 适合谁

- 想找方向的独立开发者
- 需要快速验证市场的新团队
- 要进入一个新市场的产品负责人
